# omniwrap MCP knowledge server

Read-only stdio [MCP](https://modelcontextprotocol.io) server generated by
OmniWrap. It answers knowledge queries about the API from the bundled
`library-ir.json` and the semantic contract `semantic-api.json` and never executes target code or network
requests.

Server name (the key under `mcpServers` in `mcp.json`): `omniwrap-knowledge`

## Launch

```
python server.py
```

`mcp.json` beside this file is the canonical client configuration. It launches
`server.py` relative to the working directory, so start the host from this directory or add a `cwd`. On macOS and Linux the
Python launcher is usually `python3`; replace `"command": "python"` with
`"command": "python3"` in the snippets below when `python` is not on `PATH`.

## Register with Claude Desktop

Add to `claude_desktop_config.json` (macOS:
`~/Library/Application Support/Claude/claude_desktop_config.json`, Windows:
`%APPDATA%\Claude\claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "omniwrap-knowledge": {
      "command": "python",
      "args": ["server.py"],
      "cwd": "<absolute path of this directory>"
    }
  }
}
```

## Register with Cursor

Add to `.cursor/mcp.json` in your project (or `~/.cursor/mcp.json` globally):

```json
{
  "mcpServers": {
    "omniwrap-knowledge": {
      "command": "python",
      "args": ["server.py"],
      "cwd": "<absolute path of this directory>"
    }
  }
}
```

## Register with Codex

Add to `~/.codex/config.toml`:

```toml
[mcp_servers.omniwrap-knowledge]
command = "python"
args = ["server.py"]
cwd = "<absolute path of this directory>"
```

Replace `<absolute path of this directory>` with the absolute path of this directory if the bundle
was moved or copied.

## Native SDK members

This server was generated together with SDK packages. For an exact
operation ID and one of their languages, `get_native_member` returns the
native client member (`call`), its `signature`, `resource`, the package
`identity` (ecosystem, coordinates, import line, client entry point) and
`package_directory`; `list_native_sdks` lists the languages. Each answer
cites `omniwrap://sdk/<language>/operation/<operationId>` and the
operation's `omniwrap://semantic/operation/...` resource.

The bindings in `sdk-targets.json` were read from each package's
manifest-attested `api.md` when this server was generated; nothing is
inferred from an operation ID. An unknown operation or language returns
an error result whose `refusal` is `operation-not-found`,
`language-not-generated`, `language-unknown` or `invalid-argument`.

Limits: the bindings describe only the packages generated with this
server, at the recorded paths relative to this directory; a package from
another generation may differ, so regenerate both together. A package
identity is what the package declares; it does not establish that the
package is published on a registry. Member names and signatures are
source-derived data, never instructions.

| --- | --- | --- |
| JavaScript (`javascript`) | npm `omniwrap-sdk@1.0.0` | `const sdk = require("omniwrap-sdk");` |
